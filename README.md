### Краткое описание проекта:
#### Тема проекта
Управление оборудованием в дата-центре (стойки, серверы, сервисы, инциденты).

#### Назначение
Разрабатываемая реляционная база данных предназначена для централизованного учёта и мониторинга IT-инфраструктуры дата-центра. Система позволяет отслеживать размещение оборудования, управлять жизненным циклом серверов, контролировать работоспособность сервисов, фиксировать инциденты и вести журнал технического обслуживания.

#### Основные сущности и их роль

|Сущность| Назначение|
|:---|:---|
|**racks** (стойки)|Хранение информации о физическом размещении оборудования|
|**server_statuses** (справочник статусов)|Справочник возможных состояний сервера|
|**servers** (серверы)|Учёт серверного оборудования: hostname, модель, ресурсы (CPU, RAM), IP-адрес, серийный номер, ОС, привязка к стойке и статусу|
|**services** (сервисы)|Фиксация программных сервисов, запущенных на серверах|
|**incident_priorities** (приоритеты инцидентов)|Справочник уровней приоритета с указанием нормативного времени реакции|
|**incidents** (инциденты)| Журнал сбоев и проблем: привязка к серверу и/или сервису, приоритет, время обнаружения и устранения|
|**maintenance_log** (журнал обслуживания)| Регистрация плановых и внеплановых работ|
|**servers_audit** (аудит статусов)|Автоматическая запись истории изменения статуса серверов с указанием времени и инициатора|

#### Ключевые возможности

- Контроль размещения серверов по стойкам с учётом энергомощности.
- Отслеживание текущего состояния каждого сервера.
- Учёт запущенных сервисов и их статусов.
- Фиксация инцидентов с привязкой к оборудованию и приоритетам.
- Хранение истории обслуживания и времени простоев.
- Аудит изменений статусов серверов.
- Каскадное удаление сервисов при удалении сервера.
- Защита целостности данных через внешние ключи и ограничения.

#### Обоснование ограничений

- `PRIMARY KEY` задан для каждой таблицы, чтобы каждая запись имела стабильный идентификатор.
- `FOREIGN KEY` связывают серверы со стойками и статусами, сервисы и инциденты с серверами, а журнал обслуживания и аудит с обслуживаемым оборудованием. Это защищает БД от ссылок на несуществующие объекты.
- `NOT NULL` используется для обязательных бизнес-полей: названия стойки, расположения, hostname, модели сервера, статуса и ключевых атрибутов инцидентов.
- `UNIQUE` задан для hostname, IP-адреса, имени стойки, статуса сервера и уровня приоритета, потому что эти значения должны однозначно идентифицировать объект или справочник.
- `CHECK` проверяет корректность числовых значений: положительную мощность стойки, количество CPU/RAM, диапазон порта, неотрицательное время простоя и корректный порядок дат инцидента.

#### Обоснование индексов

Индексы добавлены на внешние ключи и наиболее частые поля фильтрации: стойка, статус сервера, hostname, IP-адрес, дата инцидента, приоритет, дата обслуживания и дата аудита. Это ускоряет запросы из `queries.sql`, где часто используются `JOIN`, `WHERE`, сортировка по датам и поиск по конкретному серверу.

#### Инструкция по проверке

Для проверки нужен PostgreSQL и утилита `psql`.

```bash
createdb dc_equipment_rgr
psql -d dc_equipment_rgr -f schema.sql
psql -d dc_equipment_rgr -f data.sql
psql -d dc_equipment_rgr -f functions.sql
psql -d dc_equipment_rgr -f triggers.sql
psql -d dc_equipment_rgr -f queries.sql
psql -d dc_equipment_rgr -f demo.sql
```

После проверки базу можно удалить:

```bash
dropdb dc_equipment_rgr

Сценарий `demo.sql` является полной демонстрацией проекта: показывает наполненность таблиц, ограничения, индексы, связи между сущностями, аналитические запросы, 4 функции, 2 триггера и каскадное удаление сервисов при удалении сервера.

#### Запуск через Docker Compose

При первом запуске контейнера PostgreSQL автоматически выполнит `schema.sql`, `data.sql`, `functions.sql` и `triggers.sql`.

```bash
docker compose up -d
```

Подключение к базе внутри контейнера:

```bash
docker compose exec postgres psql -U rgr_user -d dc_equipment_rgr
```

Подключение к базе с компьютера, если нужен локальный `psql`:

```bash
psql -h localhost -p 5433 -U rgr_user -d dc_equipment_rgr
```

Проверка запросов:

```bash
docker compose exec postgres psql -U rgr_user -d dc_equipment_rgr -f /workspace/queries.sql
docker compose exec postgres psql -U rgr_user -d dc_equipment_rgr -f /workspace/demo.sql
```

Быстрая проверка количества записей:

```bash
docker compose exec postgres psql -U rgr_user -d dc_equipment_rgr -c "SELECT COUNT(*) FROM servers;"
docker compose exec postgres psql -U rgr_user -d dc_equipment_rgr -c "SELECT COUNT(*) FROM services;"
docker compose exec postgres psql -U rgr_user -d dc_equipment_rgr -c "SELECT COUNT(*) FROM incidents;"
```

Остановка контейнера:

```bash
docker compose down
```

Полная очистка контейнера и тома с данными, чтобы автоматическая инициализация выполнилась заново:

```bash
docker compose down -v
```
